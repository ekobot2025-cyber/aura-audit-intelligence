AI-BASED FRAUD DETECTION SYSTEM MENGGUNAKAN DEEP LEARNING

## 1. PROJECT OVERVIEW

Build a modern, secure, responsive web application called:

# DETEKSI FRAUD

### AI-Based Document Forensics & Financial Anomaly Detection System

The application is designed to assist auditors, financial officers, organizations, universities, government institutions, and internal control units in identifying **indications of fraud, document manipulation, abnormal pricing, potential mark-up, duplicate transactions, inconsistencies between financial documents, and suspicious transaction patterns**.

IMPORTANT:

The application must NEVER automatically accuse a person, vendor, or organization of committing fraud.

All AI results must be presented as:

* Indication
* Anomaly
* Suspicious pattern
* Risk
* Requires verification
* Recommended for auditor review

Use terminology such as:

> "Indikasi Potensi Fraud"

and NOT:

> "Fraud Terbukti"

The final determination remains the responsibility of authorized auditors/investigators.

# 33. MVP PRIORITY

Do NOT attempt to implement every advanced AI model immediately.

The first usable MVP MUST focus on:

1. Secure document upload
2. OCR / document extraction
3. Metadata analysis
4. Reference price database
5. Price anomaly detection
6. Cross-document comparison
7. Fraud Risk Score
8. Explainable findings
9. Auditor review
10. Dashboard
11. Reports

Advanced deep-learning document manipulation detection should use a modular placeholder/service architecture until a validated model and dataset are available.

DO NOT fake deep-learning detection.

If a trained model is unavailable, clearly show:

"Advanced Forensic Model Not Configured"

rather than generating fabricated confidence scores.

# 35. CRITICAL DEVELOPMENT RULES

Do not fabricate AI results.

Do not create fake forensic confidence scores.

Do not label anomalies as proven corruption.

Do not expose sensitive financial documents.

Do not hard-code fraud rules.

Do not hard-code reference prices.

Do not hard-code AI provider.

Do not place API keys in frontend.

Do not use mock data after production data is available.

Keep AI findings explainable.

Keep human auditor in the decision loop.

Every risk score must have traceable contributing factors.

Every detected anomaly must point to supporting evidence.

All important actions must create an audit log.

# 36. FINAL PRODUCT VISION

The final application should behave like an:

AI-ASSISTED FRAUD INVESTIGATION WORKSPACE

rather than a simple fraud classifier.

The system should answer four questions:

1. WHAT is suspicious?
2. WHY is it suspicious?
3. WHERE is the supporting evidence?
4. WHAT should the auditor verify next?

The application should combine:

Document Forensics
+
Financial Analytics
+
Machine Learning
+
Explainable AI
+
Human Auditor Review

to help organizations identify financial anomalies earlier while maintaining responsible, evidence-based decision making.
